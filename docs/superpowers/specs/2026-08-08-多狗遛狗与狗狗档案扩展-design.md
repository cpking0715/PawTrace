# 多狗遛狗与狗狗档案扩展 设计文档

- 日期：2026-08-08
- 项目：PawTrace 遛狗热力图 Demo（`demo/`，原生 HTML/CSS/JS + Leaflet）
- 状态：已获用户批准

## 背景与目标

用户反馈两个问题：
1. 同时选择多只狗遛狗时，地图只显示第一只狗的标记，且点击狗标记无法查看狗的信息
2. 狗狗档案缺少年龄外的完整信息（毛色、喜好、脾气、体重等）

目标：支持多狗同时遛狗（多标记独立展示、可点击查看档案），并扩展狗狗档案字段，同时保持现有"清晨公园"视觉体系与交互模式（底部卡片、标签多选、按钮单选）。

## 数据模型

`dogsData` 每条记录扩展为：

```js
{
  id, name, emoji, breed,
  size,      // 小型/中型/大型（按钮单选）
  age,       // 幼犬/青年/老年（按钮单选，即"年龄阶段"）
  color,     // 新增：毛色（色板单选：黄色/白色/黑色/棕色/花色/灰色）
  weight,    // 新增：体重（数字，单位 kg，可空）
  likes,     // 新增：喜好多选标签：零食/玩具/游泳/奔跑/社交/安静
  tags,      // 更名语义为「脾气」：好动爱玩/胆小怕生/温顺/活泼/粘人/高冷/不喜欢大狗/不喜欢小狗/会护食/社会化良好
  vaccine    // 已接种/未接种/部分接种
}
```

字段命名保持 `tags` 不变（减少改动面），UI 文案改为「脾气」。

## 多狗遛狗

### 状态结构（app.js）

```js
let walkState = {
  isWalking: false,
  dogs: [],        // [{ id, name, breed, emoji, color }] 选中狗的摘要数组（替代原 dogName/dogBreed/dogEmoji）
  startLat, startLng, startTime,
};
let dogMarkers = [];   // L.marker 数组（替代原 dogMarker）
```

### 行为

- `startWalkingPage()`：读取全部选中的 `.dog-select-card.selected`，生成 `walkState.dogs` 摘要数组；任一狗不存在则直接 return（现有守卫）；无选中仍 alert 拦截。
- `showWalkMarkersOnMap()`：
  - 清除旧 `dogMarkers`（逐个 removeLayer）
  - 每只狗在起点附近错开排布：第 i 只狗位置 = `start + (i * 0.0008, i * 0.0006)` 的固定偏移，保证标记不重叠且可独立点击
  - 每只狗创建 `L.marker` + `L.divIcon`（dog-map-marker：emoji + 名字），`zIndexOffset: 900 + i`
  - 每个标记绑定 `click` → `showDogCard(dog)`（DOM 事件经 Leaflet 冒泡，带 `L.DomEvent.stopPropagation` 防止触发地图隐藏）
  - 移动模拟：每 4 秒对每只狗做独立小幅随机移动（`dogMarkers[i].setLatLng(...)`），同时更新对应摘要位置
- `hideWalkMarkers()`：遍历清除 `dogMarkers` 并置空数组
- `switchTab('map')` 恢复逻辑不变（isRestore 判断沿用 walkMapTimer）

### 状态栏与结束弹窗

- `updateWalkStatusBar()`：`walkStatusDogEmoji` 区域改为横向排列全部狗的 emoji（多个 `<span>`）；`walkStatusDogName` 显示全部名字，用「、」连接（如「豆豆、旺财」）
- `endWalkFromMap()`：`endWalkModal` 中新增狗 emoji 横排行（显示本次遛狗的所有狗），时长/距离逻辑不变

## 狗信息卡

新增底部卡片元素 `#dogInfoCard`（复用 spotCard 的样式体系，独立 DOM 避免与公园卡状态冲突）：

- 结构：头部（大号 emoji 头像 + 名字 + 编辑按钮）、信息行（品种 · 体型 · 年龄 · 体重）、毛色行（色点 + 毛色名）、脾气标签行、喜好标签行、疫苗状态行
- `showDogCard(dog)`：从 `dogsData` 查最新数据填充并加 `show` 类
- `hideDogCard()`：移除 `show` 类
- 关闭方式：地图 `click`（与 spotCard 一致）、卡片关闭按钮
- 「编辑档案」按钮 → `hideDogCard()` + `openDogEdit(dog.id)`（复用现有编辑页，保存后落在狗狗列表页，用户可自行返回地图，遛狗状态保持）
- 缺失字段容错：`weight` 为空显示「-」；`color/likes` 为空不渲染对应行

## 编辑表单（index.html + initDogEditPage）

新增/修改：

1. 「性格标签」区块 → 标签文字改「脾气」，`#editTags` 选项扩充为 10 个（好动爱玩/胆小怕生/温顺/活泼/粘人/高冷/不喜欢大狗/不喜欢小狗/会护食/社会化良好）
2. 新增「毛色」：`#editColor` 按钮单选组（btn-group），选项：黄色/白色/黑色/棕色/花色/灰色，默认黄色
3. 新增「喜好」：`#editLikes` 标签多选组（tag-cloud），选项：零食/玩具/游泳/奔跑/社交/安静
4. 新增「体重」：`#editWeight` 数字输入框（input type=number，placeholder「如 8.5」，后缀 kg）
5. `openDogEdit()`：回填 color/weight/likes（单选高亮、输入值、多选标签 active）；新增模式设默认值（黄色、likes 空、weight 空）
6. `btnSaveDog` 保存逻辑：读取新字段，`likes` 无选中保持空数组，`weight` 空串 → null
7. 编辑页返回按钮逻辑不变

## 错误处理

- 无选中狗开始遛狗：alert「请至少选择一只狗狗」（现有逻辑，保留）
- 选中狗的 id 在 dogsData 中不存在：跳过该狗（防御）
- weight 非数字输入：浏览器 number input 校验，保存时 `parseFloat` 失败置 null
- 遛狗中编辑档案：保存后停在列表页，返回地图 Tab 后标记按 isRestore 恢复

3. 档案编辑支持毛色/体重/喜好/脾气，保存后在地图弹卡与编辑页均正确显示
4. 原有单狗遛狗、结束、Tab 切换、狗狗 CRUD 流程无回归
