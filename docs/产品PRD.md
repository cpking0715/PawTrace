## 一、产品概述

### 1.1 产品简介

| 项目 | 内容 |
|------|------|
| 产品名称 | 狗遇 |
| 产品载体 | 微信小程序 |
| 产品定位 | 零社交压力的遛狗热力图工具 |
| 一句话描述 | 看一眼地图，选条好路线，遛狗随缘遇见 |
| 目标平台 | iOS / Android（微信生态内） |
| 技术形态 | 微信小程序（Taro / 原生框架） |

**产品本质**：狗遇不是社交产品，而是一款**基于位置信号的遛狗决策工具**。它聚合附近正在遛狗的位置信息，以热力图的形式呈现，帮助用户选择遛狗路线和目的地。用户之间**零线上交互**——没有私信、没有好友、没有关注、没有评论，只有纯粹的**位置信号聚合与展示**。

**核心理念**：

- **零社交压力**：不组局、不私聊、不加好友，彻底消除社恐用户的心理负担
- **信号即数据**：用户上报的不是"我在哪"，而是"这里有遛狗信号"，数据聚合后成为公共决策参考
- **隐身优先**：默认隐身浏览，只有主动选择上报时才暴露位置信号，且信号中不含任何个人身份信息
- **随缘遇见**：产品不承诺社交，但为偶发的线下碰面创造条件——"遛着遛着就遇见了"

### 1.2 产品背景与目标

#### 市场背景

中国宠物市场正处于高速增长期，以下数据支撑了产品的市场机会：

- **市场规模**：2025年中国宠物行业市场规模突破3000亿元，年复合增长率约15%，其中犬类相关消费占比约45%
- **犬只存量**：全国犬只数量约5300万只，城镇犬主约3600万人，日均遛狗需求频次约1.5-2次
- **用户画像**：25-35岁养狗人群中，62%自认为"社恐"或"内向型人格"，他们渴望带狗出门但不愿面对社交压力
- **痛点洞察**：现有社交产品（如"遛遛""狗狗社区"等）强制用户线上互动，导致社恐用户流失率高达78%；而地图类产品（高德、百度）缺乏犬类活动热力数据，无法指导遛狗决策
- **市场空白**：目前市场上没有一款产品专注于"遛狗热力图"这一垂直场景，存在明确的品类机会

#### 产品目标

| 目标层级 | 目标描述 | 衡量指标 |
|----------|----------|----------|
| 核心目标 | 为社恐养狗人群提供零压力的遛狗地点选择工具 | 周活跃信号上报数（North Star Metric） |
| 用户目标 | 让用户出门前就能知道附近哪里适合遛狗 | 地图页日均访问次数、热力图查看时长 |
| 商业目标 | 积累犬类位置数据资产，探索商业化路径 | 月活用户数（MAU）、用户留存率 |

#### 核心假设

1. **需求假设**：用户需要的是"知道哪里适合遛狗"，而非"认识谁在遛狗"
2. **行为假设**：用户愿意主动上报遛狗信号，以换取查看热力图的权利（互惠原则）
3. **价值假设**：聚合后的热力数据比单个用户的位置信息更有决策价值
4. **隐私假设**：用户对"隐身浏览"的需求远大于"展示自我"的需求

#### 成功指标（North Star Metric）

**周活跃信号上报数** = 每周有效遛狗信号上报总数（去重后）

| 阶段 | 目标值 | 时间窗口 |
|------|--------|----------|
| MVP验证期 | 200次/周 | 上线后1个月 |
| 增长初期 | 2,000次/周 | 上线后3个月 |
| 稳定运营期 | 10,000次/周 | 上线后6个月 |

**辅助指标**：

- DAU / MAU 比值（目标 > 15%）
- 7日留存率（目标 > 20%）
- 平均每次使用时长（目标 > 45秒）
- 信号上报转化率（上报用户 / 活跃用户，目标 > 30%）

### 1.3 产品范围

#### MVP包含模块

| 模块 | 说明 | 优先级 |
|------|------|--------|
| 用户&狗狗档案 | 微信授权登录、创建狗狗档案、多犬管理 | P0 |
| 遛狗热力地图 | 核心功能，热力图展示、信号聚合、筛选器 | P0 |
| 遛狗状态上报 | 上报遛狗信号、GPS定位、信号生命周期管理 | P0 |
| 狗狗友好地点 | 静态POI标记与浏览 | P1 |
| 设置与协议 | 权限引导、隐私说明、用户协议、账号管理 | P0 |

#### V1坚决不做的功能清单

以下功能在V1版本中**严格禁止开发**，无论来自任何方向的需求压力：

| 功能 | 不做的原因 |
|------|------------|
| 私信/聊天 | 违背"零线上交互"核心原则 |
| 留言/评论 | 引入社交压力，破坏工具属性 |
| 好友/关注 | 形成社交关系链，偏离产品定位 |
| 动态广场/朋友圈 | 变成社交平台，增加运营负担 |
| 创建遛狗局/报名活动 | 从工具变成活动平台，增加复杂度 |
| 配种信息 | 引入商业化和纠纷风险 |
| 宠物商城 | 分散核心功能注意力 |
| 宠物医疗 | 与核心场景无关 |
| 直播/短视频 | 内容运营方向，违背轻量工具定位 |
| 积分/等级体系 | 游戏化运营在验证核心假设前无意义 |

#### 后续迭代方向概述

- **V1.1**：狗狗卡通形象自动生成（AI风格转换）、遛狗回忆录（批量上传+模板+分享）、双定位模式（手机GPS+定位器）、地图卡通形象显示/隐藏、遛狗兼容性提醒、遛狗自动记录、天气遛狗指数、微信分享卡片
- **V2.0**：时段推荐引擎、遛狗成就系统、"常遇信号"标记、附近宠物医院、会员订阅、POI广告系统
- **V3.0**：年度回忆录（自动生成年报）、形象进化系统（解锁配饰/背景）、形象DIY（手动调整配饰）、狗狗定位器生态（开放API）、O2O导流、品牌营销

## 二、目标用户

### 2.1 用户群体定义

#### 核心用户：25-35岁都市独居/未婚养狗青年

| 维度 | 描述 |
|------|------|
| 年龄 | 25-35岁 |
| 城市 | 一线及新一线城市（北京、上海、广州、深圳、杭州、成都等） |
| 居住状态 | 独居或与伴侣/朋友合租，无子女 |
| 养狗情况 | 养1只狗，以中小型犬为主（柯基、柴犬、泰迪、比熊、法斗等） |
| 性格特征 | 自称"社恐"或"内向"，不喜欢主动社交，但内心渴望与同频的人产生自然连接 |
| 遛狗习惯 | 每天遛狗1-2次，每次30-60分钟，通常在小区附近或固定公园 |
| 核心痛点 | 不知道附近哪里适合遛狗；担心遇到不友好的狗（大型犬、未拴绳犬）；不想在遛狗时被搭讪 |
| 使用场景 | 出门前打开小程序看热力图，选择信号多且适合自己的路线 |
| 典型代表 | "小柯，28岁，程序员，养了一只柯基，每天下班后遛狗，不想跟人聊天但又怕狗遇到冲突" |

#### 次核心用户：多犬家庭、大型犬主人

| 维度 | 描述 |
|------|------|
| 年龄 | 28-40岁 |
| 养狗情况 | 养2只及以上犬只，或养大型犬（金毛、拉布拉多、哈士奇、德牧等） |
| 核心痛点 | 需要找到适合多犬同时遛的开阔场地；大型犬主人需要避开小型犬密集区域，避免冲突 |
| 使用场景 | 通过筛选器查看"大型犬友好"区域，或避开"小型犬密集"区域 |
| 典型代表 | "阿杰，32岁，设计师，养了2只哈士奇，需要找开阔场地让它们撒欢，同时避开人多的地方" |

#### 边缘用户：代遛狗的中老年人

| 维度 | 描述 |
|------|------|
| 年龄 | 50-65岁 |
| 角色 | 帮子女代遛狗，或受雇代遛 |
| 核心痛点 | 不熟悉周围环境，不知道哪里适合遛狗 |
| 使用场景 | 子女推荐小程序后，被动使用热力图功能 |
| 典型代表 | "王阿姨，58岁，退休，帮女儿遛泰迪，只看地图上哪里颜色深就去哪里" |

### 2.2 用户需求分析

#### 核心需求（Must Have）

1. **知道附近哪里适合遛狗**
   - 用户需要在出门前就能了解附近哪些区域有遛狗活动
   - 热力图是最直观的展示方式，颜色深浅代表信号密度
   - 用户期望看到实时的、基于当前位置的数据

2. **避开不适合的狗**
   - 用户需要知道附近是否有护食犬、攻击性犬、未拴绳的大型犬
   - 通过性格标签聚合展示，帮助用户预判风险
   - 风险提示功能：当某区域有"护食"或"不喜欢大狗"标签时，自动提醒

3. **找到适合自己狗狗的遛狗环境**
   - 小型犬主人希望找到"小型犬聚集"的区域
   - 大型犬主人希望找到"大型犬友好"的开阔场地
   - 幼犬主人希望找到"社会化良好"标签较多的区域

#### 次要需求（Should Have）

4. **找到狗狗友好地点**
   - 允许进入的公园、有饮水点的绿地、有垃圾桶的步道
   - 用户自发标记的友好地点，形成UGC POI库

5. **记录遛狗历史**
   - 查看自己过去遛狗的路线和频率
   - 统计每周/每月遛狗次数和时长

#### 潜在需求（Nice to Have）

6. **无压力的偶遇社交**
   - 产品不主动提供社交功能，但当用户多次在同一区域看到热力信号时，可能会自然产生"常遇"的感觉
   - V2.0可考虑"常遇信号标记"功能（"这个时间段经常有信号"），但仍不提供身份识别

### 2.3 用户场景

#### 场景1：出门前看热力图选择遛狗目的地

**用户画像**：
- 姓名：小柯
- 年龄/职业：28岁，互联网公司产品经理
- 居住情况：上海浦东某小区，独居
- 狗狗信息：柯基"豆豆"，2岁，性格标签"胆小怕生+社会化良好"，体型小型犬
- 使用设备：iPhone 15，微信 8.0

**场景背景**：
晚上7点，下班回家吃完晚饭，准备带豆豆出门遛弯。豆豆是只胆小的柯基，遇到大型犬容易紧张，所以小柯习惯出门前先看看附近哪里适合去。

**详细操作流程**：

1. **打开小程序**
   - 在微信下拉搜索"狗遇"或从最近使用列表中点击打开
   - 小程序冷启动约1.5秒，展示品牌启动页：
     - 背景色：浅米色 `#FFF8F0`，带细微的纸质纹理（CSS noise texture）
     - 中央：品牌Logo（一只简笔柯基剪影，线条圆润，主色调 `#FF8C42` 暖橙色）
     - Logo下方：品牌名"狗遇"二字，字体为圆润的手写风格（如"站酷快乐体"），字号28px，颜色 `#333`
     - 底部Slogan："看一眼地图，选条好路线"，字号14px，颜色 `#999`，字间距2px
     - 启动页整体淡入动画（opacity 0→1，300ms ease-out）
   - 自动检测登录态有效（本地Storage中token未过期 + 服务端静默校验），跳过登录页
   - 启动页到地图页的过渡：启动页向上滑出（translateY 0→-100%，400ms），地图页从底部淡入

2. **地图加载与定位**
   - 地图页加载过程中先展示骨架屏（Skeleton）：
     - 灰色占位块模拟地图底图区域
     - 右上角两个按钮占位（筛选 + 遛狗按钮）
     - 底部TabBar占位
     - 骨架屏带微光扫过动画（shimmer effect，从左到右，1.5s循环）
   - 腾讯地图SDK初始化完成（约0.5-1秒），骨架屏淡出，真实地图淡入
   - 地图以当前小区位置为中心加载（经纬度：121.5256, 31.2452）
   - 默认缩放级别15，可视范围约覆盖1公里半径
   - 地图定位到中心点时有一个从高空俯视缓缓降落的动画（zoom从10渐变到15，600ms ease-out），给用户"降落到位"的空间感
   - **页面顶部状态栏**：
     - 高度44px，半透明白色毛玻璃背景（backdrop-filter: blur(10px)）
     - 左侧：📍图标 + 当前位置文字"浦东新区XX路XX小区"，字号13px，颜色 `#333`
     - 文字超出屏幕宽度时省略号截断，点击可展开完整地址
     - 右侧：无按钮（保持简洁）
   - **地图右下角**：浮动按钮【⊕ 回到我的位置】
     - 圆形按钮，直径44px，白色背景 + 轻投影（box-shadow: 0 2px 8px rgba(0,0,0,0.15)）
     - 图标为定位针样式，颜色 `#FF8C42`
     - 当前已在中心位置时隐藏，拖拽地图后出现（淡入动画200ms）
   - **地图右上角按钮组**（垂直排列，间距12px）：
     - 【🔍 筛选】：圆形按钮，直径44px，白色背景，漏斗图标，颜色 `#666`
     - 【🐕 我正在遛狗】：圆角矩形按钮，高度44px，宽度自适应（文字+图标），背景色 `#07C160`（微信绿），白色文字，字号14px，字重600
   - **底部TabBar**：
     - 高度56px + 安全区域padding，白色背景，顶部1px分割线 `#E5E5E5`
     - 3个Tab：🗺️ 热力地图（选中态，图标+文字均为 `#07C160`）| 🐕 我的狗狗（未选中，`#999`）| ⚙️ 设置（未选中，`#999`）
     - 选中Tab图标有轻微弹跳动画（scale 1.0→1.15→1.0，300ms）

3. **浏览热力图**
   - 地图SDK加载完成后，前端向后端请求热力聚合数据（API: `/api/v1/heatmap?lat=31.2452&lng=121.5256&radius=2000&resolution=8`）
   - 请求期间地图正常显示，热力色块从透明渐显（opacity 0→1，500ms fade-in）
   - 热力色块渲染完成，地图上可见3个热力区域：
     - **小区南门方向**（距当前位置约400米）：橙黄色色块（H3 hex cell），表示4-6个信号
       - 色块颜色 `#F5A623`，透明度75%
       - 六边形边长约80像素（对应当前缩放级别）
     - **小区东门方向**（距当前位置约300米）：浅绿色色块，表示1个信号
       - 色块颜色 `#A8D08D`，透明度40%
     - **北侧公园**（距当前位置约800米）：橙色色块，表示7-10个信号
       - 色块颜色 `#E87C2A`，透明度85%
   - 色块边缘做高斯模糊处理（blur radius 8px），与地图底图自然融合，不显生硬
   - 色块上方叠加一层细微的粒子闪烁动效（每3秒随机几个光点从色块中浮起再消失），暗示"这里有活生生的狗狗在活动"

4. **点击热力色块查看详情**
   - 小柯点击南门方向的橙黄色色块
   - **交互动效**：

     - 其他色块透明度降低至30%（突出当前选中）
     - 地图中心微微偏移，将色块移到屏幕中上方，为底部卡片留出空间（300ms ease-in-out）
   - **聚合卡片弹出**：

- 隐身用户无法看到自己的位置标记（因为根本没有上报信号，地图上不会有自己的标记）
- 隐身模式与上报模式的切换完全由用户主动触发，产品不会通过弹窗、提示等方式引导用户上报
- 隐身用户的地图操作（拖拽、缩放、点击）响应速度与上报用户完全一致，无任何功能限制
- 隐身用户不消耗任何服务端资源（不发送上报请求），仅请求热力图数据和友好地点数据
- 隐身用户看到的聚合卡片与上报用户完全一致（同样的信息、同样的交互），不存在功能降级

#### 模块1：用户登录与狗狗档案

##### 1.1 微信授权登录

**功能说明**：

用户首次打开小程序时，通过微信授权完成登录。无需手机号、无需密码、无需验证码，最大程度降低注册门槛。登录后获取用户微信OpenID作为唯一标识。

**交互逻辑**：

1. 用户打开小程序，进入启动页（展示品牌Logo + 一句话slogan："看一眼地图，选条好路线"）
2. 启动页展示1.5秒后，自动进入登录引导页
3. 登录引导页展示：
   - 产品功能简介（3张轮播卡片：热力图展示、信号上报、隐身浏览）
   - 底部【微信快捷登录】按钮（绿色，微信品牌色 #07C160）
   - 按钮下方小字：登录即表示同意《用户协议》和《隐私政策》（可点击跳转）
4. 用户点击【微信快捷登录】→ 调用微信 `wx.getUserProfile` 获取头像和昵称
5. 授权成功 → 检查是否已有狗狗档案 → 无则跳转档案创建页 → 有则直接进入热力地图

**异常处理**：

| 异常场景 | 处理方式 |
|----------|----------|
| 用户拒绝微信授权 | 提示"需要微信授权才能使用"，按钮保持可点击状态，用户可重试 |
| 网络异常 | Toast提示"网络连接失败，请检查网络后重试"，提供【重试】按钮 |
| 微信版本过低不支持API | 检测微信版本，低于7.0.0提示"请升级微信至最新版本" |
| 服务端异常 | Toast提示"服务暂时不可用，请稍后重试"，3秒后自动关闭 |

**边界条件**：

- 用户每次打开小程序时静默检查登录态，过期则自动续期（使用 `wx.login` 获取新code换取session_key）
- 登录态有效期30天，过期后需重新授权
- 同一微信账号在同一设备上只维护一个用户身份

##### 1.2 创建狗狗档案

**功能说明**：

用户登录后必须至少创建一条狗狗档案才能使用热力地图功能。档案信息用于信号上报时的标签聚合，帮助其他用户了解该区域的狗狗特征。

2. 页面顶部提示："创建狗狗档案后即可使用热力地图"
3. 表单字段：
   - **狗狗昵称**（必填）：文本输入，2-10个字符，支持中英文和emoji
   - **狗狗体型**（必填）：单选按钮组，选项为"小型犬（≤10kg）""中型犬（10-25kg）""大型犬（>25kg）"

   - **性格标签**（必填，至少选1个）：多选标签组，选项为：
     - 🏃 好动爱玩
     - 😨 胆小怕生
     - 🐕 不喜欢大狗
     - 🐩 不喜欢小狗
     - 🍖 会护食
     - 🤝 社会化良好
   - **疫苗状态**（选填）：单选，选项为"已接种全部疫苗""部分接种""未接种"，仅自己可见，不参与热力图聚合
   - **狗狗头像**（选填）：支持从相册选择或拍照，上传后自动裁剪为正方形，图片大小限制5MB以内
4. 填写完成后点击【保存】→ 校验必填字段 → 保存成功 → 提示"档案创建成功！" → 跳转热力地图

**异常处理**：

| 异常场景 | 处理方式 |
|----------|----------|
| 昵称为空或超长 | 输入框下方红色提示"请输入2-10个字符的昵称" |
| 未选择必填项 | 点击保存时，未填项高亮抖动，Toast提示"请完善必填信息" |
| 头像上传失败 | Toast提示"图片上传失败，请重试"，不影响档案保存（头像变为默认头像） |
| 图片超过5MB | 选择图片后提示"图片过大，请选择5MB以内的图片" |

**边界条件**：

- 最多创建10条狗狗档案（超出提示"最多可创建10条狗狗档案"）
- 性格标签最多选择5个（防止用户全选导致标签失去筛选意义）
- 档案创建后随时可编辑修改
- 未创建档案的用户可以浏览设置页面，但无法进入热力地图（地图入口显示"创建狗狗档案后即可使用"）

#### 模块2：遛狗热力地图（核心）

##### 2.1 地图展示与定位

**功能说明**：

热力地图是产品的核心页面，用户打开小程序后默认进入此页面。基于腾讯地图SDK，展示用户当前位置周边的遛狗信号热力图。

**交互逻辑**：

1. 进入地图页 → 请求位置权限（`wx.getLocation`）
2. 权限授予 → 地图以用户当前位置为中心加载，默认缩放级别15（约覆盖1公里范围）
3. 地图加载完成后，渲染热力色块（叠加层）
4. 用户可拖拽、缩放地图，地图中心移动后自动请求新范围的热力数据
5. 地图右下角显示【回到当前位置】按钮（用户拖拽地图后出现）

**位置权限处理**：

| 场景 | 处理方式 |
|------|----------|
| 首次请求，用户授予 | 正常加载地图和热力数据 |
| 首次请求，用户拒绝 | 显示权限引导页："需要位置权限才能查看附近遛狗信号"，提供【去设置】按钮 |
| 之前拒绝过 | 每次进入地图页都显示引导页，引导用户去设置中开启 |
| 定位失败（GPS信号弱） | Toast提示"定位失败，请移动到开阔区域"，显示上次已知位置的热力图（如有） |
| 用户设备无GPS | 提示"您的设备不支持定位功能，无法使用热力地图" |

##### 2.2 热力色块渲染

**功能说明**：

使用H3六边形网格（Hexagonal Hierarchical Spatial Index）对GPS信号进行空间聚合，将同一网格内的多个信号合并为一个热力色块。色块颜色深浅表示该区域的信号密度。

**技术方案**：

- 使用Uber H3网格系统，V1.0采用分辨率 `res=8`（六边形边长约460米）
- 每个六边形网格内统计当前有效信号数量和标签分布
- 热力色块通过Canvas叠加在地图上，与地图缩放级别联动

**色块渲染规则**：

| 信号数量 | 色块颜色 | 透明度 | 含义 |
|----------|----------|--------|------|
| 1个信号 | 浅绿色 | 40% | 有1个遛狗信号 |
| 2-3个信号 | 黄绿色 | 60% | 有2-3个遛狗信号 |
| 4-6个信号 | 橙黄色 | 75% | 有4-6个遛狗信号 |
| 7-10个信号 | 橙色 | 85% | 有7-10个遛狗信号 |
| 10个以上信号 | 深红色 | 90% | 有10个以上遛狗信号 |

**交互逻辑**：

1. 热力色块随地图缩放自动调整大小和密度
2. 缩放级别 < 12 时，不显示热力色块（避免信息过载）
3. 缩放级别 12-14 时，使用 H3 res=7（更大网格）聚合
4. 缩放级别 >= 15 时，使用 H3 res=8（当前方案）
5. 色块边缘做高斯模糊处理，视觉更柔和

##### 2.3 点击热力点位查看详情

**功能说明**：

用户点击热力色块时，弹出聚合信息卡片。**卡片中不包含任何用户昵称、头像等个人身份信息**，仅展示聚合后的标签统计。

**交互逻辑**：

1. 用户点击热力色块 → 色块轻微放大动画（scale 1.0 → 1.1）
2. 从地图底部弹出聚合卡片（半屏弹窗，可上拉展开至2/3屏）
3. 卡片内容：
   - **地点名称**：逆地理编码获取（如"朝阳公园南门"），若无POI则显示"XX路与XX路交叉口"
   - **当前信号数量**：醒目数字展示（如"5个遛狗信号"）
   - **聚合标签统计**：
     - 体型分布：🐕 小型犬 ×2 🐕 中型犬 ×2 🐕 大型犬 ×1
     - 年龄分布：🐶 幼犬 ×1 🐕 青年犬 ×3 🐕 老年犬 ×1
     - 性格标签：🤝 社会化良好 ×3、😨 胆小怕生 ×1、🏃 好动爱玩 ×2
   - **风险提示**（如有）：
     - ⚠️ "该区域有护食犬只，请注意看管"
     - ⚠️ "该区域有不喜欢大狗的犬只，大型犬请注意"
   - **底部操作**：
     - 【导航前往】按钮（调用微信内置地图导航）
     - 【关闭】按钮
4. 点击卡片外部区域或下滑关闭卡片

**异常处理**：

| 异常场景 | 处理方式 |
|----------|----------|
| 点击时信号已过期 | 卡片显示"该区域信号已更新"，不展示过期数据 |
| 逆地理编码失败 | 地点名称显示"未知位置"，展示经纬度 |
| 网络请求失败 | 卡片显示"数据加载失败"，提供【重试】按钮 |

**边界条件**：

- 同时只能展示一个聚合卡片，点击另一个色块时自动关闭当前卡片
- 聚合标签最多展示5个高频标签，其余折叠为"更多"
- 风险提示仅当存在"护食""不喜欢大狗""不喜欢小狗"标签时触发

##### 2.4 地图筛选器

**交互逻辑**：

1. 地图右上角【筛选】按钮（图标：漏斗形）
2. 点击后弹出筛选面板（右侧滑出，宽度为屏幕70%）
3. 筛选项：
   - **体型筛选**（多选）：小型犬 / 中型犬 / 大型犬（至少选1个，默认全选）
   - **性格筛选**（多选）：好动爱玩 / 胆小怕生 / 不喜欢大狗 / 不喜欢小狗 / 会护食 / 社会化良好（默认不选，选择后只显示包含对应标签的区域）
   - **年龄段筛选**（多选）：幼犬 / 青年犬 / 老年犬（默认全选）

5. 筛选状态在地图右上角显示角标数字（如"筛选中(2)"）

- 筛选面板打开时，地图仍可拖拽和缩放

#### 模块3：遛狗状态上报

##### 3.1 上报遛狗信号

**功能说明**：

用户主动上报遛狗信号，将自己的狗狗位置信息以匿名方式贡献到热力图中。上报后，用户的位置信号会被聚合到热力图中，但不会暴露任何个人身份信息。

**交互逻辑**：

1. 地图右上角【我正在遛狗】按钮（主色调按钮，醒目但不突兀）
2. 点击后弹出上报确认弹窗：
   - 标题："上报遛狗信号"
   - 选择本次出门的狗狗（多选复选框，从狗狗档案列表获取）
   - 显示当前GPS定位地址（逆地理编码结果）
   - 提示文字："信号有效期90分钟，到期后自动消失。上报后你的位置将以匿名方式显示在热力图中。"
   - 【确认上报】按钮 / 【取消】按钮
3. 用户选择狗狗并确认后：
   - 前端获取当前GPS坐标（`wx.getLocation`，type: gcj02）
   - 将坐标 + 选中狗狗的标签信息发送至后端
   - 后端写入信号数据库，返回信号ID
   - 前端进入"遛狗中"状态：
     - 地图右上角按钮变为【遛狗中 89:59】（倒计时）
     - 底部出现浮条："正在遛狗中，点击结束"
4. 上报成功后，热力图立即更新（包含新上报的信号）

**异常处理**：

| 异常场景 | 处理方式 |
|----------|----------|
| 未选择狗狗 | 【确认上报】按钮置灰，提示"请至少选择一只狗狗" |
| GPS定位失败 | Toast提示"定位失败，请移动到开阔区域后重试" |
| GPS精度过低（>500米） | 提示"定位精度较低，可能影响热力图准确性，是否继续？" |
| 上报频率过高（<5分钟内重复上报） | 提示"你刚上报过信号，请在X分钟后再试" |
| 网络异常 | Toast提示"上报失败，请检查网络后重试" |
| 已有信号未过期时再次上报 | 提示"你当前有进行中的遛狗信号，是否结束当前信号并重新上报？" |

##### 3.2 信号生命周期管理

**功能说明**：

每个遛狗信号有明确的生命周期：创建 → 有效 → 过期/手动结束 → 失效。信号有效期90分钟，到期后自动从热力图中移除。

**交互逻辑**：

1. **信号进行中**：
   - 地图右上角显示倒计时【遛狗中 XX:XX】
   - 底部浮条显示"正在遛狗中，点击结束"
   - 点击浮条 → 弹出确认弹窗："确定结束本次遛狗吗？信号将立即从热力图中消失。"
   - 确认 → 信号立即失效 → 热力图更新 → 恢复初始状态
2. **信号自动过期**：
   - 90分钟倒计时归零 → 信号自动标记为过期
   - 前端轮询或WebSocket推送通知信号已过期
   - 地图右上角按钮恢复为【我正在遛狗】
   - 底部浮条消失
   - 热力图自动更新（移除过期信号）
3. **倒计时精度**：
   - 前端本地倒计时，每30秒与服务器同步一次
   - 防止用户修改本地时间绕过过期机制

**边界条件**：

- 同一用户同一时刻只能有一个有效信号
- 信号过期后，历史上报记录保留（用于遛狗统计）
- 小程序被杀死后重新打开，如果信号仍在有效期内，自动恢复遛狗状态和倒计时
- 手机关机/断网期间，信号按原计划90分钟过期（服务端计时）

##### 3.3 防虚假上报机制

**功能说明**：

为防止用户虚假上报（如在家上报、恶意刷信号），需要建立基础的防作弊机制。

**防作弊策略**：

| 策略 | 说明 | 处理方式 |
|------|------|----------|
| GPS偏差检测 | 检测GPS坐标是否在合理范围内（如与上次位置距离过大） | 单次移动距离 > 50km，标记为可疑信号，不参与热力聚合 |
| 高频限流 | 防止频繁上报/结束 | 同一用户5分钟内不可重复上报 |
| 信号密度异常 | 同一网格内信号数远超正常值 | 触发限流，该网格信号数上限为50 |
| 举报入口 | 用户可举报可疑信号 | 设置页提供举报入口，填写举报原因 |

| signal_end | 结束遛狗信号 | duration（时长）, end_type（手动/自动） | 分析遛狗时长 |
| heatmap_click | 点击热力色块 | cell_id, signal_count | 分析用户关注点 |
| filter_use | 使用筛选器 | filter_type, filter_values | 分析筛选需求 |
| friendly_view | 查看友好地点 | location_city | 统计功能使用率 |
| friendly_create | 标记友好地点 | location, tags | 统计UGC贡献 |
| share_action | 分享操作 | share_type, share_target | 统计分享行为 |
| error_report | 异常上报 | error_type, error_msg | 技术监控 |

### 8.2 页面PV/UV统计

所有页面均需自动采集PV（页面浏览量）和UV（独立用户数），包含以下通用参数：

- page_path：页面路径
- referrer_path：来源页面路径
- stay_duration：页面停留时长
- user_id：用户标识（脱敏）
