# 狗遇 - 详细设计方案 V1.0

> 版本：V1.0  
> 日期：2026年8月8日  
> 产品定位：零线上交流，只聚合狗狗位置信号；地图热力看附近遛狗信号，不组局、不私聊、不加好友，主人线下随缘碰面。

### 1.2 用户使用路径

#### 画像A - 小林典型使用路径

```
首次使用：
微信发现"狗遇"小程序 → 授权登录 → 引导创建狗狗档案（麻薯）
→ 填写体型(小型犬)、性格标签(好动爱玩、胆小怕生) → 进入地图

日常使用（出门前）：
打开小程序 → 自动定位 → 查看热力地图
→ 看到附近公园有黄色/橙色热点 → 点击热点查看详情
→ "中小型犬×3，好动爱玩×2" → 决定去这个公园
→ 到达后点击"我正在遛狗" → 选择麻薯 → 确认上报
→ 遛狗结束，手动点击"结束遛狗" → 信号立即过期

纯隐身模式（不暴露自己）：
打开小程序 → 只看热力图 → 不上报信号 → 选地点出门
```

#### 画像B - 阿杰典型使用路径

```
日常使用：
打开小程序 → 点击右上角筛选按钮 → 勾选"大型犬"
→ 地图刷新，只显示有大型犬信号的区域
→ 发现附近绿道有一处热点 → 点击查看详情
→ "大型犬×2，社会化良好×1" → 决定去那里
→ 到达后上报信号 → 大福和其他金毛/拉布拉多玩耍
```

#### 画像C - 王阿姨典型使用路径

```
日常使用：
打开小程序 → 看热力图 → 避开红色密集区域
→ 找到一片绿色/空白区域（附近草坪）→ 带豆豆去
→ 不需要筛选、不需要上报，只看地图
→ 偶尔标记一个“狗狗友好地点”（干净草坪）
```

### 1.3 新增使用场景 `V1.5/V2.0`

#### 场景A：卡通形象生成（小林 + 豆豆） `V1.5`

```
场景描述：
小林给豆豆拍了一张可爱的照片，打开“卡通形象库”页面
→ 点击“拍照生成” → 选择Q版风格 → 点击“生成预览”
→ AI生成Q版卡通形象，小林很满意 → 点击“保存”
→ 返回形象库，将该Q版形象设为默认
→ 之后地图上豆豆的头像就变成了Q版卡通形象
```

#### 场景B：定位器绑定与自动切换（阿杰 + 大福） `V2.0`

```
场景描述：
阿杰给金毛大福买了一个Tabcat定位器
→ 打开“定位器管理”页 → 点击“绑定新设备”
→ 蓝牙搜索找到Tabcat → 点击连接 → 绑定成功
→ 设为默认定位方式
→ 下次出门遛大福时，开始遛狗后自动切换为定位器模式
→ 路线轨迹更精确，实时位置缓存到Redis
```

#### 场景C：回忆录分享（阿杰 + 大福） `V1.5`

```
场景描述：
阿杰翻看大福的遛狗回忆录
→ 打开“回忆录”页面 → 选择“大福的遛狗日记”
→ 时间线展示每次遛狗的照片、路线、距离
→ 点击“分享”按钮 → 生成精美分享卡片（含小程序码）
→ 分享到朋友圈，朋友扫码可以查看回忆录
→ 回忆录状态更新为“shared”
```

| tags | Array\<String\> | 是 | - | 性格标签 | 至少1个，最多5个，枚举值见下方 |
| vaccineStatus | String | 否 | null | 疫苗状态 | 枚举：completed/partial/none，仅自己可见 |

| createdAt | Date | 自动 | 当前时间 | 创建时间 | - |
| updatedAt | Date | 自动 | 当前时间 | 更新时间 | - |

**性格标签枚举值（tags）**：

| 枚举值 | 显示文案 | 说明 |
|--------|---------|------|
| active | 好动爱玩 | 精力旺盛，喜欢跑跳 |
| shy | 胆小怕生 | 对陌生环境和人较紧张 |
| no_large_dogs | 不喜欢大狗 | 与大型犬相处紧张 |
| no_small_dogs | 不喜欢小狗 | 对小型犬不耐烦 |
| food_guard | 会护食 | 吃东西时保护食物 |
| socialized | 社会化良好 | 与其他狗友好相处 |

**体型枚举值（size）**：

| 枚举值 | 显示文案 | 体重范围 |
|--------|---------|---------|
| small | 小型犬 | ≤10kg |
| medium | 中型犬 | 10-25kg |
| large | 大型犬 | >25kg |

**年龄枚举值（age）**：

| 枚举值 | 显示文案 | 年龄范围 |
|--------|---------|---------|
| puppy | 幼犬 | 0-1岁 |
| young | 青年犬 | 1-7岁 |
| senior | 老年犬 | 7岁以上 |

**业务约束**：每个用户最多创建3个狗狗档案（MVP限制）。

### 3.3 交互规范

#### 3.3.1 加载状态规范

| 场景 | 加载形式 | 说明 |
|------|---------|------|
| 首次进入页面 | 全屏骨架屏 | 灰色占位块+脉冲动画 |
| 下拉刷新 | 顶部loading指示器 | 主色旋转图标 |
| 按钮操作 | 按钮内loading + 禁用 | 防止重复提交 |
| 地图数据加载 | 热力图区域脉冲动画 | 半透明灰色波纹 |
| 图片加载 | 渐进式加载 | 先模糊缩略图，再清晰原图 |

#### 3.3.2 空状态规范

| 场景 | 插画 | 主文案 | 副文案 | 操作按钮 |
|------|------|--------|--------|---------|
| 无狗狗档案 | 孤独小狗 | "还没有狗狗档案" | "创建档案后才能使用热力地图" | "创建档案" |
| 地图无信号 | 小狗看地图 | "附近暂时没有遛狗信号" | "试试上报你的信号" | "上报信号" |
| 无POI数据 | 空地图 | "附近暂无狗狗友好地点" | "快来标记第一个吧" | "标记地点" |
| 网络异常 | 断网图标 | "网络连接失败" | "请检查网络设置后重试" | "重试" |

#### 3.3.3 错误提示规范

| 类型 | 形式 | 持续时间 | 示例 |
|------|------|---------|------|
| 轻提示 | Toast（居中） | 2秒自动消失 | "操作成功"、"网络异常" |
| 操作反馈 | Toast（带图标） | 2秒自动消失 | ✅成功 / ❌失败 |
| 确认操作 | 模态弹窗 | 需手动关闭 | "确定删除该档案？" |
| 引导操作 | 半屏弹窗 | 需手动关闭 | "需要位置权限" |
| 表单错误 | 输入框下方红字 | 实时显示 | "请输入狗狗名字（最长10字）" |

#### 3.3.4 弹窗规范

- 模态弹窗：圆角24rpx，padding 48rpx，遮罩 `rgba(0,0,0,0.5)`
- 底部弹出：圆角32rpx（仅顶部），最大高度70%屏幕
- ActionSheet：底部弹出，选项间距2rpx分割线，取消按钮与选项间距16rpx
- 所有弹窗支持点击遮罩关闭

## 四、API接口设计

### 4.1 接口规范

**基础URL**：`https://api.pawtrace.com/api/v1`

**认证方式**：
- 基于微信openId的JWT认证
- 请求头携带：`Authorization: Bearer <token>`
- Token有效期：30天，支持无感刷新
- 登录接口外所有接口均需认证

**请求格式**：
- Content-Type: `application/json`
- 文件上传: `multipart/form-data`

**统一响应格式**：
```json
{
  "code": 0,
  "message": "success",
  "data": { ... }
}
```

**错误码定义**：

| 错误码 | 说明 | HTTP状态码 |
|--------|------|-----------|
| 0 | 成功 | 200 |
| 1001 | 参数校验失败 | 400 |
| 1002 | 缺少必填参数 | 400 |
| 2001 | 未授权（token无效/过期） | 401 |
| 2002 | 微信登录失败 | 401 |
| 2003 | 权限不足 | 403 |
| 3001 | 资源不存在 | 404 |
| 4001 | 请求频率超限 | 429 |
| 4002 | GPS精度不足 | 400 |
| 4003 | 不在中国境内 | 400 |
| 4004 | 已达上报上限 | 400 |
| 5001 | 服务器内部错误 | 500 |
| 5002 | 内容审核未通过 | 422 |
| 4005 | 超过10个形象上限 | 400 |

**接口分期概览**：

| 版本阶段 | 模块 | 说明 |
|---------|------|------|
| **V1.0 MVP核心** | 用户模块、狗狗档案、遛狗信号、POI地点、举报、管理后台 | 核心地图热力功能，验证产品可行性 |
| **V1.5 扩展** | 卡通形象、回忆录、遛狗记录、附近宠物医院 | 丰富用户体验，提升留存 |

### 4.4 遛狗信号模块接口 `V1.0`

#### POST /api/signals

**说明**：上报遛狗信号

**请求**：
```json
{
  "dogIds": ["507f1f77bcf86cd799439012"],
  "location": {
    "lat": 22.5431,
    "lng": 114.0579
  },
  "accuracy": 15
}
```

**校验规则**：
- `dogIds`：必填，非空数组，所有ID必须属于当前用户
- `location.lat`：必填，范围 3.86-53.55（中国纬度范围）
- `location.lng`：必填，范围 73.66-135.05（中国经度范围）
- `accuracy`：选填，若提供则必须 ≤100米
- 频率限制：同一用户60秒内最多上报1次
- 活跃信号限制：同一用户最多2个活跃信号

**响应**：
```json
{
  "code": 0,
  "data": {
    "_id": "507f1f77bcf86cd799439020",
    "expiresAt": "2026-08-08T11:30:00Z",
    "h3Index": "88283082b7fffff",
    "nearestHotspot": {
      "h3Index": "88283082a3fffff",
      "distance": 350,
      "dogCount": 3
    }
  }
}
```

**业务逻辑**：
1. 校验所有dogIds归属当前用户
2. 校验GPS坐标在中国境内
3. 校验GPS精度（accuracy ≤ 100m，若未提供则默认通过）
4. 检查频率限制（Redis `ratelimit:signal:{userId}`，TTL=60s，max=1）
5. 检查活跃信号数量（≤2）
6. 计算H3 Level 8索引
7. 写入Redis：`signal:{signalId}` → 信号数据，TTL=5400s
8. 写入Redis：`user:signals:{userId}` → 追加signalId
9. 写入MongoDB：signals集合
10. 异步触发热点聚合更新
11. 返回信号信息和最近热点

**错误码**：
- 4002：GPS精度不足（accuracy > 100m）
- 4003：不在中国境内
- 4004：已达活跃信号上限（2个）
- 4001：请求过于频繁（60秒内重复上报）

#### GET /api/signals/heatmap

**说明**：获取热力图数据

**请求参数**（Query String）：
```
sw_lat=22.50&sw_lng=114.00&ne_lat=22.58&ne_lng=114.12
&filters[sizes]=small,medium
&filters[excludeTags]=shy,food_guard
```

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| sw_lat | Number | 是 | 可视区域西南纬度 |
| sw_lng | Number | 是 | 可视区域西南经度 |
| ne_lat | Number | 是 | 可视区域东北纬度 |
| ne_lng | Number | 是 | 可视区域东北经度 |
| filters.sizes | String | 否 | 体型筛选，逗号分隔 |
| filters.excludeTags | String | 否 | 排除标签，逗号分隔 |

**响应**：
```json
{
  "code": 0,
  "data": {
    "hotspots": [
      {
        "h3Index": "88283082b7fffff",
        "center": { "lat": 22.543, "lng": 114.058 },
        "dogCount": 3,
        "signalCount": 2,
        "dogs": [
          { "size": "small", "tags": ["active", "shy"] },
          { "size": "small", "tags": ["socialized"] },
          { "size": "medium", "tags": ["active", "socialized"] }
        ],
        "heatValue": 2.5,
        "intensity": 0.6,
        "latestSignalAt": "2026-08-08T10:25:00Z"
      }
    ],
    "updatedAt": "2026-08-08T10:30:00Z"
  }
}
```

**业务逻辑**：
1. 先查Redis缓存（按可视区域内的h3Index集合）
2. 缓存未命中则从MongoDB查询：`$geoWithin` + `$box` 查询可视区域
3. 应用筛选条件：按dogs的size和tags过滤
4. 按H3 cell聚合，计算heatValue（含时间衰减）
5. 归一化intensity（当前区域最大heatValue为基准）
6. 更新Redis缓存（TTL=60s）
7. 返回热点列表

### 5.2 Redis Key设计

| Key模式 | 数据类型 | TTL | 说明 | 示例值 |
|---------|---------|-----|------|--------|
| `signal:{signalId}` | Hash | 5400s (90min) | 活跃信号缓存 | `{userId, dogIds, h3Index, lat, lng, expiresAt}` |
| `user:signals:{userId}` | Set | 5400s | 用户当前活跃信号ID集合 | `{signalId1, signalId2}` |
| `hotspot:{h3Index}` | String(JSON) | 60s | 热点聚合缓存 | `{dogCount, dogs, heatValue, intensity}` |
| `ratelimit:signal:{userId}` | String(Int) | 60s | 信号上报限流计数器 | `1`（60秒内最多1次） |
| `ratelimit:upload:{userId}` | String(Int) | 3600s | 图片上传限流 | `5`（1小时内最多10次） |
| `ratelimit:report:{userId}:{targetId}` | String | 86400s | 举报限流（24h内同目标1次） | `1` |
| `session:{userId}` | String(JSON) | 2592000s (30天) | 用户会话缓存 | `{token, loginAt, deviceId}` |
| `tracker:location:{trackerId}` | String(JSON) | 300s (5min) | 定位器最新位置 `V2.0` | `{lat, lng, accuracy, updatedAt}` |
| `walk:route:{walkId}` | List | 7200s (2h) | 遛狗路线实时缓存 `V1.5` | `[[lng,lat], ...]` 每30秒追加 |

**关系说明**：
- users → dogs：一对多，一个用户最多3个狗狗档案

- signals → hotspots：多对一，同一H3 cell内的信号聚合为一个热点
- users → pois：一对多，用户可创建多个POI
- users → reports：一对多，用户可提交多条举报
- reports 可指向 signals/pois（多态关联，通过targetType区分）

### 6.5 部署方案

**Docker Compose（单机部署）**：
```yaml
version: '3.8'
services:
  nginx:
    image: nginx:alpine
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./nginx.conf:/etc/nginx/nginx.conf
      - ./ssl:/etc/nginx/ssl
    depends_on:
      - app
    restart: always

  app:
    build: ./server
    environment:
      - NODE_ENV=production
      - MONGODB_URI=${MONGODB_URI}
      - REDIS_URL=${REDIS_URL}
      - COS_BUCKET=${COS_BUCKET}
      - COS_REGION=ap-shanghai
      - WECHAT_APPID=${WECHAT_APPID}
      - WECHAT_SECRET=${WECHAT_SECRET}
      - JWT_SECRET=${JWT_SECRET}
    depends_on:
      - mongo
      - redis
    restart: always

  mongo:
    image: mongo:6
    volumes:
      - mongo_data:/data/db
    restart: always

  redis:
    image: redis:7-alpine
    command: redis-server --maxmemory 128mb --maxmemory-policy allkeys-lru
    volumes:
      - redis_data:/data
    restart: always

volumes:
  mongo_data:
  redis_data:
```

**Nginx配置要点**：
- HTTPS强制跳转
- SSL证书：腾讯云免费SSL证书
- 反向代理至Node.js应用（端口3000）
- 请求限流：100次/分钟/IP
- Gzip压缩
- 静态资源缓存

**环境变量管理**：
- 使用 `.env` 文件管理敏感配置
- 生产环境通过Docker环境变量注入
- 禁止在代码中硬编码任何密钥/凭证
