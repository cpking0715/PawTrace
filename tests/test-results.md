## 观察项（非失败，建议改进）

1. **UI 文案瑕疵**：遛狗页狗狗信息显示「柯基 · 小型**型** · 好动爱玩」—— [app.js](file:///d:/MyProjects/PawTrace/demo/app.js#L343) 中 `dog.size}型` 与数据中的「小型」重复拼接「型」。建议改为 `${dog.size}` 或在数据中去掉「型」。
2. **favicon 缺失**：`demo/` 无 `favicon.ico`，浏览器请求返回 404。建议补充图标（P2）。
3. **测试方法说明**：TC-05 使用 CDP 脚本化 `element.click()` 时曾出现动画未完成的假失败，改用真实鼠标点击后稳定通过；功能本身无缺陷。后续回归建议用真实输入事件驱动。

## 缺陷修复记录（2026-08-08）

### 第一轮：遛狗定位缺陷

用户反馈「点击开始遛狗后返回地图，没有定位到我当前位置且没有显示我的狗」，定位到两个根因并已修复：

1. **[BUG] 90 秒静默自动结束遛狗**：`startWalkingPage()` 的遛狗页计时器在 90s 后自动调用 `endWalkingPage()`，静默清除标记/状态栏/遛狗状态。用户操作超过 90 秒返回地图时即看到「没有定位、没有狗」。
   - 修复：移除自动结束逻辑，圆环进度改为每 90 秒循环一圈（[app.js](file:///d:/MyProjects/PawTrace/demo/app.js#L412-L427)），遛狗需用户手动结束。
   - 验证：TC-26 通过。
2. **[BUG] “当前位置”取地图浏览中心**：`startWalkingPage()` 用 `map.getCenter()` 作为定位起点，用户浏览过地图（如拖到深圳）后开始遛狗，定位点/狗标记会出现在浏览位置而非城市中心。
   - 修复：「当前位置」固定为城市中心人民公园附近 (30.62, 104.06)（[app.js](file:///d:/MyProjects/PawTrace/demo/app.js#L395-L403)），无论地图浏览到何处，开始遛狗都定位回当前位置。
   - 验证：TC-27 通过。

### 第二轮：档案编辑保存丢失品种（本轮发现）

3. **[BUG] 编辑狗狗保存后品种变为「未知」**：TC-30 执行中发现，编辑豆豆保存后，狗狗列表与遛狗信息卡中品种（柯基）丢失，显示「未知」。
   - 根因：`btnSaveDog` 保存时硬编码 `breed: '未知'`（表单无品种字段），编辑已有狗时覆盖了原 breed。
   - 修复：编辑已有狗时保留原 breed（`breed: existing ? existing.breed : '未知'`，[app.js](file:///d:/MyProjects/PawTrace/demo/app.js#L805-L811)）。
   - 验证：修复后编辑豆豆保存 → 列表/信息卡仍显示「柯基」，新增狗 breed 仍为「未知」（行为不变）。

## 结论

**30/30 用例通过（100%）**，Demo 的核心主流程（地图热力图、筛选、地点页、单/多狗遛狗完整生命周期、狗信息卡、狗狗 CRUD 含新增字段保存回填）均符合预期；本轮三个缺陷（90s 自动结束、定位偏移、编辑丢失品种）已修复并通过回归验证。

## 缺陷发现与修复记录（第二轮）

1. **[BUG] 遛弯页结束绕过战报导致数据丢失**：TC-47 验证发现，遛弯页点「结束遛弯」走独立 UI 重置路径（`endWalkingPage`），未经过 `confirmEndWalk()`，战报大卡恒为 1、狗 chip 为空、公式校验失败。
   - 修复：`endWalkingPage()` 改为只调用 `confirmEndWalk()`，统一结束出口。
   - 验证：修复后 ?v=10 全过；TC-60 回归复验通过。
2. **[BUG] 崽崽圈页碰爪成功后时间线不刷新**：TC-52 验证发现，在崽崽圈页碰爪成功后返回，`switchTab('circle')` 同页短路不触发渲染，动态数仍为 0。
   - 修复：碰爪确认处理器中，当前页为崽崽圈页时显式调用 `renderCircleTimeline()`（玩伴列表页同理调 `renderFriendsList()`）。
   - 验证：?v=11c 复测通过。
3. **[预防] 距离浮点显示**：计划原样 `walkDistance = trackDistance(...)` 会产生小数米，改用 `Math.round(trackDistance(...))`。
